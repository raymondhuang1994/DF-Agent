# DF Agent 0.6.0

在当前 Windows 桌面软件的本地会话中，作为 Router/Advisor 选择并衔接已安装的 df-mcp、DataLab 和 ETF 评论草稿 v2。df-mcp 负责来源目录、索引、检索和版本证据，DataLab 负责计算；入口负责选择流程、交接输入和审核结论，并保留本机配置、明确反馈及有来源的个人/项目记忆。

公开项目：[GitHub 仓库](https://github.com/raymondhuang1994/DF-Agent) · [已发布版本](https://github.com/raymondhuang1994/DF-Agent/releases) · [安装说明](docs/LOCAL_INSTALL.md) · [试用与测试指南](docs/TRY_IT.md)

原 TeamAdvisor 项目从 0.4.0 起统一命名为 **DF Agent**。新入口为 `$df-agent`，插件安装标识为 `df-agent@df-agent`；已有设置和记忆的兼容方式见 [改名与兼容说明](docs/RENAME_0.4.0.md)。

0.6.0 明确专业分工，并按实际能力消费 df-mcp 的来源目录与兼容证据包装，不建立第二份资料目录或 reader。新特性依赖所选 df-mcp 实际支持；已有原生配置和响应继续可用。检测器新增 reader 核心/依赖文件完整性检查，以及 CSV、TSV、XLSX 对应的 DataLab 依赖检查；这不代表资料可读或业务结论正确。

沿用“原资料只读、指定目录获授权写入”的文件策略。旧版 `N:\digital finance` 仅保留为受保护资料根，不自动选为本轮来源；实际来源和运行目录由 df-mcp 的已确认配置确定。既有目录建议见 [0.5.0 规则与文件策略](docs/POLICY_0.5.0.md)，首次创建和索引仍遵循本轮授权。

## 可以做什么

- **选择必要流程：**已有资料就直接分析或写作，需要补证据时再使用已配置、获准的资料来源。可串联“找资料 → 算指标 → 写草稿”。
- **汇总与解释数据：**通过 DataLab 做资金流、渠道收入等表格分析，核对单位、期间和分项合计，保留结果依据。
- **按产品资料写评论：**通过 ETF 评论技能生成指定数量的内部草稿，区分产品事实和风格参考，不从旧案例补造业绩。
- **复用本机设置和项目经验：**授权后保存技能来源与解释器；按个人、项目只读查询用户已明确要求记住的口径、偏好和经验，支持更新、回退与删除。
- **记录明确反馈：**在明确的内容、目录和操作授权内保存用户采纳、修改或拒绝的原因，将选中的内容整理成记忆候选；候选经明确授权发布后才能供后续任务使用。

插件不自带这三项专业技能，也不自动读取所有聊天或同事电脑。公司资料连接由每位使用者按自己的资料范围和权限配置。

## 使用

安装后在新会话调用 `$df-agent`，直接描述任务：

- “帮我完成首次设置，记住本机可用的技能和运行环境。”
- “按这份产品资料写三条中文社区评论，给我内部审阅。”
- “按附件计算各基金净流入，核对日期、币种和汇总口径，解释主要变化。”
- “记住：项目 A 的净流入口径是申购减赎回，赎回金额按正数输入。”
- “采用第二版，修改原因是要先交代适用场景；保存为这个项目的经验。”
- “查看项目 A 的记忆，把已经过时的这条删除。”

长文先简列核心假设；关键目标不清楚时先提问，多种解读先给选项；结果简洁、结论先行。润色只改指定部分，存疑数据单独提醒。已有输入足够就省略检索，不需要计算就省略 DataLab。缺少某项技能时说明缺项，继续可独立完成的步骤。首次设置与后续自检由顾问处理；本地配置变化会重新检查。

## 主要能力

| 能力 | 行为 |
|---|---|
| 五条协作准则 | 先对齐、结论先行、局部修改、交付自检、原资料只读 |
| 目录与操作授权 | 默认不写文件；按本任务授权限定目录及操作，索引与资料分离 |
| 一次设置、后续复用 | 授权后保存技能根、来源和解释器；后续只读检测变化 |
| 证据与结论审核 | 对照来源范围、版本、分页、提取缺口和业务口径；保留 DataLab 原始校验状态 |
| 明确反馈记录 | 记录采纳/修改/拒绝及用户原因，关联任务、产物和来源版本 |
| 个人/项目记忆 | 候选与发布分离，按身份及项目读取，带来源、有效期和明确替代关系 |
| 更正与遗忘 | 更新、范围内回退及删除；已删除内容不因回退复活 |

记忆只保存选中的经验，不自动抓取聊天记录。记忆不授予访问或发布权限，历史数字仍需核对最新来源。团队共享、同事电脑和真实公司连接的验收状态见 [验证报告](docs/VALIDATION.md)。

## 安装与开发

完整仓库包含 `.agents/plugins/marketplace.json` 和 `plugins/df-agent/`。下载完整源码后，在当前客户端支持的 CLI 中运行：

```powershell
codex plugin marketplace add '<完整源码目录>' --json
codex plugin add df-agent@df-agent --json
```

通过 SkillHub 分发时，使用根级 `SKILL.md` 的完整 `.skill` 包，保留参考文档、脚本和相对路径。构建命令：`python tools/check_package.py --skill-package <仓库外路径>/DF-Agent-0.6.0.skill`。具体安装、更新和新会话检查见 [安装说明](docs/LOCAL_INSTALL.md)。

开发检查只需 Python 3.11+ 标准库：

```powershell
python -X utf8 -B -m unittest discover -s tests -v
python -X utf8 -B tools/check_package.py
python -X utf8 -B tools/check_package.py --zip '<项目外目录>\DF-Agent-Source-0.6.0.zip' --plugin-zip '<项目外目录>\DF-Agent-0.6.0.zip'
```

0.6.0 当前源码共 134 项本地回归，按整组及单项复验汇总为 133 通过、1 跳过，新增检测的最后一次 15 项复验全部通过；技能结构和离线发布包校验通过。具体范围及尚未验证项目见 [0.6.0 验证](docs/VALIDATION_0.6.0.md)。

0.5.0 完成本地 117 项回归（116 通过、1 项因本机权限跳过）、6 项跨进程记忆集成检查及 5 项独立行为测试，详见 [0.5.0 验证](docs/VALIDATION_0.5.0.md)。更多规则场景和手工验收标准见 [测试指南](docs/TRY_IT.md)，场景定义不等于已经执行。远端 CI 以对应提交的 [实际运行结果](https://github.com/raymondhuang1994/DF-Agent/actions) 为准。此前安装记录和合成业务结果保留在 [0.4.0 验收](docs/VALIDATION_0.4.0.md) 与 [历史验证报告](docs/VALIDATION.md)，不把旧测试改写成新版业务验收。

## 文件与数据边界

入口插件独立分发；专业技能代码、Python 环境、个人路径、反馈记录、记忆库、认证和公司资料均不进入发布包。新安装默认状态在 `%LOCALAPPDATA%\DF-Agent`；没有新目录配置而旧 `%LOCALAPPDATA%\TeamAdvisor\setup.local.json` 存在时，继续使用原目录。显式指定的状态目录优先。改名不移动或复制记忆，详见 [改名与兼容说明](docs/RENAME_0.4.0.md)。自带脚本检查已声明的任务、写入根和操作，保护资料根；这不修改操作系统权限，也不隔离第三方工具。个人/项目范围由程序筛选，不是操作系统权限隔离；不要把自己的状态目录作为团队共享盘。

`sources.json` 固定本插件文件哈希与已观察的专业资源版本。`evals/` 的素材为合成数据，场景定义与实际执行证据分开保存。[设计说明](docs/MEMORY_DESIGN.md) 说明记忆方案及验证边界。
