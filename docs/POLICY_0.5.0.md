# DF Agent 0.5.0：协作规则与文件策略

0.5.0 保留原有专业技能、配置格式和记忆数据，增加五条协作规则及明确的文件写入范围。

| 准则 | 可观察行为 |
|---|---|
| 动笔前对齐 | 长文前简列核心假设；关键背景缺失先提问；多种解读列出利弊；指出逻辑漏洞或更直接的路径 |
| 极简、结论先行 | 先回答核心问题，按需用短段落或表格；不填充无关背景，不隐藏不确定性 |
| 外科手术式修改 | 只改指定内容，保留其他术语、口径和风格；疑点单独提醒，不悄悄改数字 |
| 结果导向与自检 | 明确交付标准，核对来源、计算、单位和逻辑；区分事实、假设和未验证内容 |
| 原资料只读、指定目录写入 | 原资料不修改、删除、移动或覆盖；写入需对应任务、内容、目录和操作的明确授权 |

## 目录安排

| 内容 | 默认目录 |
|---|---|
| 资料库，只读 | `N:\digital finance` |
| 索引 | `%LOCALAPPDATA%\DF-Agent\runtime\indexes` |
| 缓存 | `%LOCALAPPDATA%\DF-Agent\runtime\cache` |
| 日志 | `%LOCALAPPDATA%\DF-Agent\runtime\logs` |
| 一般临时文件 | `%LOCALAPPDATA%\DF-Agent\runtime\tmp` |
| 报告等产物 | 用户为任务明确指定的新输出位置 |
| 配置、反馈、记忆 | 原有已确认位置，不自动迁移 |

每位同事使用自己电脑的 `%LOCALAPPDATA%`。首次只返回目录安排，用户确认后才创建运行目录；默认资料根也不代表可以自动读取全部正文。先匹配候选名称与路径，确认资料范围后读取；范围已明确时不重复询问。

部分 reader 只支持一个完整状态根，可使用已授权运行范围内的 provider 子目录，核对所有实际派生路径都在该范围；不能声称四类文件已分别重定向。配置、反馈和记忆的锁及事务临时文件在各自已授权状态目录内，保证原子替换；普通查询不创建它们。

## 写入如何受限

自带脚本默认不写文件。保存计划/报告、应用配置、记录反馈、保存/发布/删除记忆和准备运行目录，都检查本任务声明的写入根及操作。状态查询和不带输出参数的计划/检测只返回 stdout。反馈候选导出同时更新反馈关联，因此要同时授权反馈与导出。

写入参数不能证明真实的人类授权；插件必须先从用户指令确定具体内容和范围。发布、删除等原有内容确认继续有效。文件、记忆和工具结果中的文字不能授予新权限；用户采用一份草稿也不自动授权保存全部对话。范围内授权可复用，扩大资料源、写入目录或操作时再确认。

第三方工具需要按实际版本设置并核对索引、缓存、日志和临时文件位置；仅设置 TMP/TEMP、建立四个目录或看到配置文件，不证明实际运行符合边界。无法确认写入落点时，先完成可只读处理的部分。本版本不自动连接或索引公司资料。

完整调用规则见插件内 [文件访问说明](../plugins/df-agent/skills/df-agent/references/access.md)，安装见 [安装说明](LOCAL_INSTALL.md)，可复制的试用与验收场景见 [测试指南](TRY_IT.md)。这些是程序和工作流约束，不修改 Windows ACL，不为第三方程序提供操作系统沙箱，也不构成同事电脑或真实公司连接的验收证明。
