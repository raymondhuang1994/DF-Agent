# 记忆服务于后续交付

当前版本把“做过什么”转成有来源、适用范围和有效期的少量经验，帮助下次任务复用口径、偏好与已批准决定。它不是聊天全文搜索，也不是全员共享知识库。

## 数据流

明确的采纳/纠正 → 反馈记录 → 精选记忆候选 → 检查来源、冲突及有效期 → 用户已明确授权的发布 → 后续任务按个人和项目检索 → 更正、替代、回退或删除。

普通业务任务只读取已发布记录，未发布候选不会出现在检索结果。个人偏好与项目决定分开，其他项目和其他身份记录不进入本轮结果。一个已发布记录只能由明确指向它的新版本替代；删除清除本程序存储的正文及历史引用，回退不复活已删除内容。

来源定位、版本和观察时间帮助使用者复核。市场事实需要有效期，过期内容不参与正常检索。即使未过期，也不能替代当轮最新资料；同一指标不同币种、日期、范围或业务定义不混用。

## 反馈与价值验证

“采用”“修改后采用”“拒绝”必须来自明确反馈。没有回复不计采纳，生成成功不计业务成功。两个首批任务分别检查：

- 产品材料转评论：事实都有来源，数量和平台语气匹配，风险及适用场景准确，不把风格例子当产品事实。
- 资金流转指标解释：数据覆盖、币种、日期、申赎符号、重复与缺失可解释，明细与总数复核，解释不超出数据支持。

本地自动测试证明存储与筛选行为，独立合成任务检查跨任务复用；这些都不能证明团队节省了多少时间。真实价值需要用获准任务比较首次采纳、修改次数、事实错误与人工处理时间。当前不宣称未经实测的收益。

## 对文章思路的取舍

参考 [Anthropic 官方示例：Dreaming with a dynamic workflow](https://github.com/anthropics/claude-cookbooks/blob/main/managed_agents/CMA_dreaming_with_a_dynamic_workflow.ipynb) 的“分析已完成任务、整理经验、版本管理、后续按需读取”思路。

本实现独立编写，未复制其平台 API，不依赖 Claude 服务；只整理用户选中的任务结果和明确反馈。发布前保留检查，不默认夜夜自动更新，不扫描其他会话或同事数据。CLI 的读取/写入职责分离是应用行为约定，没有声称 Windows 文件被只读挂载或具备账户级权限控制。

当前采用标准库 JSON 存储与命令行接口，不依赖向量数据库或外部模型，便于审查、备份和测试。后续如引入团队共享，应另外设计身份认证、项目访问控制和团队知识审批。外部备份与已导出的副本需单独清理，本地删除不能擦除操作系统备份或已分享副本。
